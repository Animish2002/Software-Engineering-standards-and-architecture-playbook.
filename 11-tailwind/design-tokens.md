# Design tokens

## What is it?

Named values (colours, spacing, radii, fonts) defined once and referenced
by utilities and components. In Tailwind v4, tokens are CSS variables
declared in `@theme`, and every utility is generated from them.

## shadcn token bridge (v4)

shadcn defines semantic colour variables (`--background`, `--primary`,
`--muted-foreground`, …) per theme; `@theme inline` maps them to Tailwind
colour utilities (`bg-background`, `text-muted-foreground`).

```css
@import "tailwindcss";
@custom-variant dark (&:is(.dark *));

:root {
  --radius: 0.625rem;
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  --primary: oklch(0.205 0 0);
  --primary-foreground: oklch(0.985 0 0);
  --muted: oklch(0.97 0 0);
  --muted-foreground: oklch(0.556 0 0);
  --destructive: oklch(0.577 0.245 27.325);
  --border: oklch(0.922 0 0);
  --ring: oklch(0.708 0 0);
  /* … the rest generated by `npx shadcn init` */
}
.dark {
  --background: oklch(0.145 0 0);
  --foreground: oklch(0.985 0 0);
  /* … */
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-destructive: var(--destructive);
  --color-border: var(--border);
  --color-ring: var(--ring);
  --radius-sm: calc(var(--radius) - 4px);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);
  --font-sans: "Inter Variable", ui-sans-serif, system-ui, sans-serif;
}

@layer base {
  * { @apply border-border outline-ring/50; }
  body { @apply bg-background text-foreground; }
}
```

## Rules

- **Use semantic tokens in components**: `bg-card`, `text-muted-foreground`, `border-border`. Never raw palette colours (`bg-gray-100`) in app code; they break in dark mode and on rebrand.
- **Add app tokens in `@theme`** when the design system needs them: `--color-success`, `--color-warning`, `--spacing-sidebar: 16rem`, `--breakpoint-3xl: 120rem`.
- **Change the look by changing tokens**, not by editing components. A rebrand is a `:root` edit.
- **Dark mode via the `.dark` class** on `<html>`, toggled by a theme provider that respects `prefers-color-scheme` and persists the choice. Every token has a dark value; components never use `dark:` for colours (tokens handle it); `dark:` is for the rare structural difference.
- **Spacing scale**: stick to the default scale (`gap-2`, `p-4`); arbitrary spacing only for measured layout constraints.

## Semantic status colours

```css
@theme inline {
  --color-success: var(--success);
  --color-success-foreground: var(--success-foreground);
  --color-warning: var(--warning);
  --color-warning-foreground: var(--warning-foreground);
}
```

Then `Badge` variants map statuses to these once.

## Typography and radius

- One `--font-sans` (and `--font-mono`); load via `@fontsource` or system stack.
- `--radius` drives all corners; adjust once.
